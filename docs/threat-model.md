# 威胁模型（归拢）

> 这份文档**不是决策**，是**一张账**：把散落在 22 条 ADR 里的"我们怕什么"归到一处，让每个新功能都能回答三个问题而不是重新辩论一遍。
> 生成方式：全部条目都来自**本机实测**或**上游原文**，没有推测；凡未核实的都标了"未核定"。

## 0. 怎么用

**四问**：① 保护什么（资产）→ ② 谁想动它（对手）→ ③ 边界在哪（谁负责）→ ④ **哪些明确不防**。

**每个新功能回答三问**：新增了什么**资产暴露**？新增了什么**对手能力**？**边界移动**了吗？

**每条 ADR 都应引用本文件的条目**（§4 的对账表就是为此而设）。

## 1. 资产（按丢失代价排序）

| 资产 | 位置 | 实测状况 |
|---|---|---|
| **设备本身** | `/data/adb`、`/system`、boot 分区 | **最贵** —— 刷坏是**硬件级**（ARB 只增不减、熔断不可逆） |
| **设备桥凭据** | `/root/.dsh/.bridge_token`（**32 字节明文**）、`.bridge_headers` | 容器内可读，且**虚拟屏与设备 shell 共用它**（实测硬需求）；拿到 = 能驱动设备能力（读屏/点按/截屏/启停应用/**虚拟屏**）→ 处置见 **ADR-021 决定 B** |
| **模型 API key** | `/root/.dsh/.credentials.yaml`（223 字节） | 容器内可读；拿到 = 烧钱 + 可读他人对话 → 处置见 **ADR-021 决定 C** |
| ~~0600 保护~~ | 两个凭证**都是 `0600` 属主 root** | ⚠️ **但容器内的 AI 现在就以 root 跑 → 0600 形同虚设，全员可读**（ADR-021 决定 C 要降权） |
| **会话数据** | `$DSH_HOME/sessions/` | 用户与 AI 说过的一切；**格式有版本，但没有加密** |
| **用户共享存储** | `/storage/emulated/0` | ⚠️ **rw bind 进容器**（见 §6.2） |
| **宿主 root** | — | 容器内一旦能改入口/挂载/模块 = **等于拿到宿主 root** |
| **可用性** | — | DSH 是常驻服务；坏了用户当天没得用 |

## 2. 对手

| 对手 | 它手上有什么 | 它想要什么 |
|---|---|---|
| **⚠️ 提示注入（头号）** | 网页 / 文件 / 工具输出里的一段文字 | **借 AI 的手做事** —— AI 不是对手，但注入让外部对手**获得 AI 的全部权限** |
| **AI 本身（犯错）** | 容器内 root、写文件、跑命令、写插件、装插件 | 没有恶意，但**会犯错**（误删、改错路径、把凭据写进日志） |
| **AI 写的插件** | **进程内代码、沙箱外、跨会话存活** | 一旦被注入污染 → **持久化**，重启还在 |
| **第三方插件上游** | 能改自己发布的内容 | 供应链 |
| **其它 App** | 普通 App 权限；**有 root 的更狠** | 数据 / 权限 |
| **同 Wi-Fi 的人** | 网络可达 | `lan` 档下的 token、会话 |
| **物理接触者** | 解锁的手机 | 一切 |
| **我们自己（手滑）** | root、MT 管理器的批量替换 | 误删 / 误改 |

> **核心洞察**：**AI 不是对手，是"对手的手"。** 所以本模型真正的议题不是"怎么拦住 AI"，而是"**AI 被注入时，爆炸半径有多大**"。
> 而当前给它的是**最大权限**：`danger-full-access` + root + `/sdcard` rw。

## 5. 不设防声明（防虚假安全感）

- **不防有 root 的攻击者** —— 整个项目建立在 root 上，root 面前一切都是纸糊的；
- **不防物理接触** —— 解锁的手机 + root = 一切；
- **不防提示注入本身** —— 只能限制**爆炸半径**，不能阻止 AI 被注入；
- **不防 DSH 上游自身漏洞** —— 上游 `SAFETY.md` 已声明"实验性、未经安全审计"；
- **不防内核 / 固件层** —— 阶段一不碰内核，也不假装防内核后门；
- **不防用户自己 `dsh-ctl purge`** —— 不可逆操作是用户自己的选择；
- **不防出网目的地** —— chroot 与宿主共享 netns（ADR-021 决定 D），**强制不了**；只保证"容器内没有全网卡监听"。

## 6. 现在开着的口子（带实测证据）

### 6.1 🟡 凭据暴露面（**已定 → ADR-021**；拆成两类，先前被混为一谈）

**（a）模型 API key** —— `~/.dsh/.credentials.yaml`（223 B）
- 泄露后果：花钱 + 能读他人对话。
- 处置：**ADR-021 决定 C**（AI 降权）后，`0600` 才真正生效。

**（b）设备桥 token** —— `~/.dsh/.bridge_token`（**32 B 明文**）
- 泄露后果：⚠️ **拿到设备操作权**（读屏 / 点按 / 截屏 / 启停应用 / **虚拟屏**）—— **比 (a) 危险得多**。
- **硬需求（实测）**：虚拟屏插件 `dsh-tool-vscreen/lib/server.cjs:75` **直接读这个文件**，并在 `:59` 带 `X-Token` 打到 DSHA 桥 3090；
  与 `adb-shell.py` 是**同一个文件、同一个 token** → **抽走它两个能力直接死**，所以不能靠"藏"解决。
- 处置：**ADR-021 决定 B**（token 出容器）+ **决定 C**（降权）。

**关键结论**：`0600` 保护**当前是纸糊的** —— 因为容器内的 AI **就以 root 跑**，root 能读任何文件，也能读别的进程的 `/proc/<pid>/environ`。
**先让 AI 降权，其它措施才有意义。**

### 6.2 ⛔ 用户存储全量暴露

- **事实**（`/proc/self/mountinfo`，实测）：
  ```
  1000002 … /storage/emulated/0 rw - bind /storage/emulated/0 rw
  1000003 … /sdcard            rw - bind /storage/emulated/0 rw
  ```
  可写性：`/storage/emulated/0` ✅ · `/DCIM` ✅ · `/Download` ✅
  顶层可见：DCIM · Documents · Download · Movies · Music · Pictures · Android · BaiduNetdisk · backups …
- **注意**：这是 **DSHA 的 proot 启动参数**加上去的（`libproot.so … -b /storage/emulated/0:/sdcard -b /storage/emulated/0`）→ **新模块形态下默认不会出现**，所以"限制"不是拆固化的东西，而是**默认不加**。
- **缺口**：ADR-016 只写了"**共享目录默认只给沙箱**"，那是**约定，没有约束力** —— 缺一条硬约束 + 申请通道。
- **根因**（上游事实）：`fs-sandbox` **只管写，读完全不管**（原文："preserving the local filesystem's read behavior"）→ **可见性只能靠挂载**。

### 6.3 🟡 出网策略（**已定 → ADR-021 决定 D**：从空词换成"可检查的判据 + 诚实的不设防"）

- **事实**：chroot **不隔离网络**（容器与宿主共享 netns）→ **在 chroot 形态下，出网目的地无法强制**。
- **可检查的**：容器内**不得有绑 `0.0.0.0` / `::` 的监听**（ADR-006 `local` 档）；`dsh-ctl status` 应报告，有则告警。
- **不设防的**：**出网目的地**（技术上强制不了）→ 已列入 §5，**不当它是保护**。
- **升级触发**：真需要强制 → 那是 **netns** 的事 → 归**阶段二**（ADR-001 已裁，触发条件见 pitfalls §B1）。

### 6.4 ⚠️ 沙箱层在本机失效（已认领，但要知道后果）

| 检查 | 结果 |
|---|---|
| `DSH_PERMISSION_MODE` | `danger-full-access`（`dsh-base/cordis.patch.yml:232,248` 用同一个变量同时决定沙箱 mode 与 approval） |
| `landlock-run --probe` | **rc=125**（内核未启用 Landlock ABI） |
| `bwrap` | **未安装** |
| `unshare -Urm` | ✅ 可用（缺的是 bwrap 这个使用者） |

→ **本机没有中间档**：要么 `danger-full-access`（DSH 层零边界），要么受限模式（**bash 完全跑不了**）。
→ 并且：**三个 mode 都不管网络与进程可见性，读取路径完全不受其文件边界保护。**

### 6.5 ⚠️ 审计面缺口：容器内看不到监听/连接

- **实测**：容器内 `/proc/net/tcp` → **Permission denied**（Android 限制 + proot 下真实 uid 是 10543）。
- → **代理人无法自证"现在有哪些端口在监听"**，只能靠宿主侧查。
- **宿主机侧实测（17 个 TCP 监听）**：
  ```
  ✅ 只在回环：127.0.0.1:3080（DSH web）· 127.0.0.1:3090（DSHA 桥）· :10156 · :10157 · :12121 · :33959 · :59568
  ⚠️ 全网卡：0.0.0.0:4466 · :::4468 · 0.0.0.0:8909 · :::8911 · :::10150 · :::10152 · :::10162 · 0.0.0.0:13178 · :::46888
  ```
- **好的一面**：我们的两个服务（3080 / 3090）**都只在回环** ✅（ADR-006 的 `local` 档现状成立）。
- **未核定**：那 9 个全网卡监听**归属未查明**（容器内看不到；`ss` 不在设备白名单里）。同 Wi-Fi 的人能碰到它们 —— 但它们**大概率不属于本项目**。**待查**。

### 6.6 ⚠️ 间接出口未收口（ADR-020 决定 F 的待定项）

- `tool-subagent`（子代理会自己跑工具）· `tool-workflow`（能跑代码）· `skill-filesystem`（技能能读文件）· `tool-web`（下载会写盘）
- → **收口不完整就等于没收**。ADR-020 已把这条写成代价，未解决。

### 6.7 ℹ️ 别人的世界可读日志（不是我们的 bug，但要知道）

- `/data/adb/ksu/log/logcat.log` 权限 **`-rw-rw-rw-`（世界可读）**，而它含**全系统日志**（19 MB × 2 代 + dmesg + sulog）。
- → 容器内**任何进程**（含 AI 写的插件）都能读到整台手机的日志片段。

## 7. 变更纪律

1. **加功能前**回答三问（资产 / 对手 / 边界）；
2. **加写盘位置**必须登记进 ADR-017 的**残留面清单**；
3. **加执行出口**必须更新 ADR-020 的**收口清单**；
4. **改边界**（挂载表 / 入口位置 / 权限面）必须同时改本文件的 §3 与 §6；
5. **§5 的"不设防"清单要定期复查** —— 某一条从"可接受"变成"不可接受"时，它就该升级成一条新 ADR。
